# Build 20260924b — atualização automática garantida + localização pedida uma vez só

## 1. Atualização automática (sem hard refresh)
Causa: o GitHub Pages manda `cache-control: max-age=600` em tudo. O `sw.js` antigo usava `fetch(req)`,
que passa pelo cache HTTP, e o `pwa.js` só comparava o localStorage com a própria ASSET_V, então
uma cópia velha nunca percebia que havia build nova.

Correção:
- `sw.js`: navegações/HTML → `fetch(url, {cache:'no-store'})` (redireciona com 302 quando há redirect);
  JS/CSS → `cache:'no-cache'` (revalida por ETag); `version.json` nunca cacheado; precache com `cache:'reload'`.
- `pwa.js`: `checkRemoteVersion()` lê `version.json?t=` (no-store) ao abrir, ao voltar ao app
  (visibilitychange/focus/pageshow) e a cada 60 s com o app visível. Se a build remota for mais nova →
  limpa Cache Storage + desregistra o SW + `location.replace(?_hv=<build>)`. Trava: 2 tentativas por
  build (sessionStorage) e intervalo mínimo de 15 s. SW registrado com `updateViaCache:'none'`.
- O hard reset **nunca** limpa o localStorage (sessão, tema, `minera_geo_*` ficam).
- `scripts/bump-build.mjs <id>`: troca a build em todos os html/js/css/webmanifest e grava `version.json`.

## 2. Localização (permissão pedida uma vez só)
Culpado: `inicio.js` chamava `getCurrentPosition` toda vez que o Início abria.
- Novo `geo.js` → `MineraGeo.obterLocalizacao({motivo, interativo, highAccuracy, timeout, fresco})`.
  - `permissions.query` = granted → posição em silêncio; denied → nunca chama a API;
    prompt/desconhecido (iOS) → só chama num toque do usuário (`interativo:true`).
  - Cache `minera_geo_last` (30 min) + flag `minera_geo_decidido`.
- Início: botão "📍 Perto de mim" (no painel de filtros). Mapa: "📍 Abrir na minha localização".
- `rg navigator.geolocation` → só `geo.js`.
